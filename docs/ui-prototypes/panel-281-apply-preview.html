    Design notes

    Tauri command surface

    The panel renders a structured value, not raw CLI stdout. The Tauri bridge would expose two commands:

    preview_apply(manifest_path: PathBuf) -> Result<ApplyPreview, ApplyPreviewError>
apply(manifest_path: PathBuf, force: bool) -> Result<ApplyResult, ApplyError>

    ApplyPreview is a superset of today's DesiredStateDiffReport (crates/defra-agent-cli/src/desired_state/mod.rs:372): same per-collection create / update / unchanged / live_only ID lists, plus the manifest field payloads (so updates can render field-level diffs) and the per-collection apply_order rank from ApplyReconcile.Collections.applyOrder.

    apply() wraps apply_bound_desired_manifest (commands/config/apply.rs:36) and returns the existing ConfigApplyReport (shared.rs:241) verbatim.

    Data shape mirrors the ApplyReconcile Lean spec

    Lean models the diff as ApplyStep = create | update (ApplyReconcile/Diff.lean:15), enumerated over the manifest's support and sorted by (collection.applyOrder, id). The panel groups rows by collection in the same order — rank 0 (backends, profiles, registries, selections) first, then 1 (behaviors), 2 (tasks, schedules), 3 (principals, event triggers) — so the rendered diff matches what the apply path would execute. Per-collection witness rows live under crates/defra-agent/proofs/Proofs/ApplyReconcile/ContractCases/Fixtures.lean; the mock datasets here are shaped to match those.

    How the panel surfaces atomicity (#246)

    The Atomicity preview block renders expected_external_state_after_abort — a compact "what readers see if apply fails at this point". Because the apply path runs inside a single DefraDB transaction (apply.rs:70-89), the answer is always "exactly the pre-apply live state" — no partial visibility, no staged-write leakage. The panel makes this property visible without requiring the operator to read the Lean spec.

    Out of scope (matches issue #281 / #57)

    • Delete semantics aren't applied; the diff shows live_only documents as a reserved red-tinted banner so a future Delete pass slots in without reshuffling the layout (tracked in #57).
    • This is a UI prototype only — no Tauri bridge, no real apply, no live-data fetch.

    Accessibility

    • Each major region is a <section> or <header> with an aria-label.
    • Error state uses role="alert" with aria-live="polite".
    • Collection headers are focusable and toggle on Enter / Space.
    • The action log advertises aria-live="polite" so screen readers announce the result of Apply / Dry-run.
    • Color is never the only signal: every diff row also carries a textual marker (+, ~, ·, −) in a mono-font column.

    Performance hints (large diffs)

    • Each collection card caps its body at max-height: 560px with overflow: auto, so a 100-row no-op group scrolls inside its card instead of stretching the page.
    • No-op groups collapse by default beyond the first 5 rows (Show all N…) so large diffs stay legible without drowning the meaningful changes.
    • For multi-thousand-row diffs the production version would virtualize the no-op group; the design accommodates this with the stable per-collection card boundary.
