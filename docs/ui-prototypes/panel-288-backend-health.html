    Design notes

    Data shape (faithful to runtime)

    This panel reads two persisted collections — no new persistence is required. The runtime owns the live state; the operator UI is a read-only projection. 

    // crates/defra-agent-protocol/schemas/inference/inference_backend.graphql
type InferenceBackend {
  backend_id: String          // unique per deployment
  name: String
  provider_kind: String       // "OpenAiCompatible" | "OpenRouter"
  endpoint: String            // OpenAI-compatible base URL (incl. /v1)
  max_concurrent: Int
  max_queue_depth: Int
  enabled: Boolean
  models: [String]
  last_probe: DateTime        // populated on probe; may be absent
  probe_status: String        // "healthy" | "unhealthy" | "unknown"
                              // | "stale" | "rate_limited" | "circuit_open"
}

// crates/defra-agent-protocol/schemas/inference/inference_call.graphql
type InferenceCall {
  call_id, runtime_instance_id, request_id, call_seq,
  backend_id, behavior_id, agent_did, call_kind, attempt,
  call_state: String          // "queued" | "running" | "completed"
                              // | "failed" | "cancelled"
  failure_reason: String      // e.g. "QueueFull", "BackendGone", provider err
  queued_at, started_at, ended_at,
  queue_depth_at_enqueue: Int,
  prompt_tokens, completion_tokens
}

    Tauri command surface

    // minimal, read-only — sufficient for this panel
list_backends_with_health() -> Vec<BackendHealthView>

struct BackendHealthView {
  // mirrors InferenceBackend
  backend_id, name, provider_kind, endpoint, models,
  enabled, max_concurrent, max_queue_depth,
  probe_status, last_probe,

  // last 10 InferenceCall rows where backend_id matches,
  // ordered by queued_at DESC
  recent_calls: Vec<InferenceCallSummary>,
}

    Implementation: one GraphQL query against InferenceBackend(order: { backend_id: ASC }) (mirrors backend_registry.rs:179–228 list_backend_records), plus a second query per backend against InferenceCall filtered by backend_id with limit: 10 and order: { queued_at: DESC }.

    Visual treatment

    The derived display state is a pure UI rollup of enabled × probe_status — it does not introduce any new runtime concept. The mapping mirrors InferenceBackend::is_available (backend_registry.rs:95) and the Lean witness backendAvailable (proofs/Proofs/Conformance/ContractCases/BoundaryRuntime.lean:197):

    • available — enabled && probe_status == "healthy"; the only case where the admission gate will admit work.
    • unhealthy — enabled && probe_status == "unhealthy"; the probe rejected the backend.
    • stale — enabled && probe_status == "stale"; the probe data itself is too old to be trusted. Treated as a warning because remediation is usually rerunning the prober, not replacing the backend.
    • rate-limited — enabled && probe_status == "rate_limited"; the backend is reachable but the provider is throttling us. Warning, not error: the condition typically resolves itself; the admission gate just shouldn't route new work to this backend right now.
    • circuit-open — enabled && probe_status == "circuit_open"; recent failures tripped a circuit breaker. The backend may be reachable but we've decided not to call it until the circuit half-opens. Warning rather than error because the state is a local decision, not a verdict on the backend itself.
    • unknown — enabled && probe_status == "unknown"; default for a newly-registered backend that has not yet been probed.
    • disabled — !enabled; operator-controlled; the row is dimmed and the gate is closed regardless of probe state.

    Gap status

    rate_limited and circuit_open are now first-class spec states (Lean witnesses + Rust availability check + UI). The runtime accepts the strings via the existing probe_status: String field, and is_available() stays false for anything other than "healthy". What is not yet in place is the runtime logic that produces these states; the panel renders them when the document carries them. Each gap below is a separate workstream:

    Capability Status What still needs to land
    Rate-limit detector spec only The Lean enum has .rateLimited and the UI renders probe_status == "rate_limited". Missing: a runtime that watches InferenceCall.failure_reason over a sliding window (e.g. consecutive HTTP 429s) and writes the state back into InferenceBackend.
    Circuit breaker spec only The Lean enum has .circuitOpen and the UI renders probe_status == "circuit_open". Missing: a controller state machine in admission/ for trip / half-open / reset transitions, plus the persistent transition log and the reset command. The reset command is deliberately out of this PR (no probe_backend / reset_backend_circuit on the Tauri surface).
    Live active / queued counters in-memory only BackendAdmissionController.{running, waiters} are atomics held in RAM and lost on restart (admission/controller.rs:23–25). To surface in the UI: either ship as a one-shot snapshot from the running process (Tauri command reads atomics) or persist a periodic checkpoint.
    Live probe action no mechanism probe_status is populated at config load (no background prober loop). A probe action needs a runtime subsystem to schedule, execute, and record the probe. This panel is read-only — there is no "Probe" or "Reset circuit" button.
    Last probe latency partial last_probe: DateTime exists on the schema (inference_backend.graphql:16); a latency field would extend the same row.
    Recent call history per backend queryable Filter InferenceCall by backend_id; terminal reasons (QueueFull, BackendGone, provider errors) are already persisted (admission/persistence.rs:84–109).

    Lean conformance

    Witnesses for the panel's status derivation live in backendHealthAdmissionCases (BoundaryRuntime.lean:214). Seven cases cover enabled × probe_status ∈ {healthy, unhealthy, unknown, stale, rate_limited, circuit_open} → admissionDecision. The bridge-snapshot consumer test drives the Tauri command with a fixture per witness and asserts the derived display state.

    Accessibility

    • Status is conveyed by three redundant channels: a coloured dot glyph (◉ / × / ! / ? / —), an uppercase text label (AVAILABLE, UNHEALTHY, …), and the row's left border colour. No information is colour-only.
    • Each row is a native <button> with aria-expanded; expand/collapse responds to Enter, Space, and click. Tab order is row-by-row.
    • The fleet summary chips are inside an aria-live="polite" region so the variation switcher announces fleet rollup changes to assistive tech.
    • Tabular numerics (font-variant-numeric: tabular-nums) on counts, queue depths, and timestamps so they do not shift as mock data cycles.

    Out of scope (per PROMPT.md)

    Tauri integration, real fetching, build tooling, multiple HTML files, ledger promotion, modifications to the backend registry or admission policy, adding new backend kinds.
