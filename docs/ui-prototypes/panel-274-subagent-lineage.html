    Design notes for impl

    Tauri command surface

    This panel is the consumer of the design spec's desktop_list_subagent_tree command (see docs/superpowers/specs/2026-05-20-desktop-operator-surfaces-design.md §"Panel 3"):

    desktop_list_subagent_tree({
  rootRequestId: string,
  agentDid?: string | null,
  includeTerminal?: boolean,
  maxDepth?: number,
}) -> SubagentTreeView

    An R5 cross-deployment snapshot is already exposed by the runtime HTTP layer at GET /subagents/dispatches?parent_request_id=<id> (see crates/defra-agent-cli/src/http/r5_dispatch.rs). The Tauri command can be a thin wrapper around that endpoint plus a local-DB walk for in-process descendants — keeping a single authoritative shape on the UI side.

    Data shape

    The tree alternates request nodes and tool-call nodes; edges carry the bridge metadata (await_mode, cancel_policy, tool_name). The minimum the panel needs per node:

    SubagentNodeView {
  requestId, sessionId?, agentDid?, behaviorId?,
  lifecycleState?, status?, subagentDepth?,
  causedByParentRequestId?, causedByParentToolCallId?
}
SubagentEdgeView {
  parentRequestId, childRequestId,
  parentToolCallId?, toolName?,
  awaitMode?, cancelPolicy?, lifecycleState?
}

    The runtime walks AgentRequest.caused_by_parent_request_id and cross-checks against AgentToolCall.child_request_id; the panel renders both edge sources so a missing bridge (e.g. unclaimed) is visible rather than silently dropped.

    Cross-deployment notes (this issue, #274)

    R5 splits a single lineage across deployments — a parent on the local deployment may dispatch a child onto a remote deployment via a spawn_subagent tool. The panel labels each request with its agent_did (deployment) so the operator can see the routing at a glance. The deployment chips at the top let the operator slice to one side of the boundary at a time. This is the surface the matrix row subagents-cross-deployment / operatorUi tracks.

    Accessibility

    • The lineage is a WAI-ARIA tree: role="tree" on the root, role="treeitem" and role="group" on children, aria-expanded on each node that has children.
    • Single tab-stop. Arrow keys move within the tree: ↑/↓ previous/next visible node, → expand or descend, ← collapse or ascend, Enter / Space selects, Home / End jump to first/last.
    • Selection is independent of expansion; aria-selected reflects the active node and the detail panel is the live region for that selection.
    • Focus restored to the previously-selected node when scenarios change so the operator does not lose their place.

    Open questions

    • Should the panel poll desktop_list_subagent_tree or subscribe via the existing snapshot-feed channel that the rail's other panels use? Polling is simpler; subscription matches background-tools and cascade-preview behavior.
    • When a parent and a child sit on different deployments, do we want to surface latency between the bridge's started_at and the child's claimed_at? Useful signal, but adds another column to a tree that's already dense.
    • "Interrupt selected" rooted at a child request shares plumbing with the composer interrupt flow (Panel 1). The cascade-preview confirmation belongs to that path — out of scope for this prototype but the button is shown for placement.
    • Truncation: should we cap depth client-side (e.g., collapse subtrees past maxDepth) or let the bridge enforce it? Today the prototype renders everything.
