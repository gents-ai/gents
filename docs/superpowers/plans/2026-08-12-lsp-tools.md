# Native `lsp` Tool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Advertise one opt-in `lsp` tool on coding behaviors so the model can run oh-my-pi language-server actions against detected built-in catalog servers, without custom servers, without bypassing the effective command policy, and without inventing new lifecycle or failure machinery.

**Architecture:** Reconcile builds an immutable `ToolSurface` generation. `static_policy = behavior ∩ ceiling ∩ runtime` is the only authority input. When `static_policy.lsp` is true and file tools are not `Off`, `build_tools` boxes an `LspTool` that borrows the host `LspPool`. The pool starts catalog servers through `spawn_managed_process` (persistent stdio, process-lifetime cancel token). File tools optionally receive an `LspWritethrough` that talks only to already-Ready clients. `session::close_session` stays a persistence write; the owner that holds both the session id and the pool calls `LspPool::close_session`. `run_agent` awaits `lsp_pool.shutdown()` after behavior slots finish.

**Tech Stack:** Lean 4 (`crates/gents/proofs`), Rust workspace crates `gents`, `gents-protocol`, `gents-schemas`, `gents-cli`, `gents-desktop-core`, `gents-desktop-bridge`; DefraDB GraphQL `ToolSelection`; stdio JSON-RPC 2.0; existing `FailureClass` / `ReportedFailure` / `nativeCommand`.

**Spec:** `docs/superpowers/specs/2026-08-12-lsp-tools-design.md` (committed). Read it first. This plan is the source of truth for code shape; any uncommitted WIP on `feat/lsp-tools` is judged against this plan, not the other way around.

- Worktree: `/Users/johnzampolin/go/src/github.com/source-inc/gents-lsp-tools`, branch `feat/lsp-tools`.
- Foundation order: Lean first, then conformance JSON, then Rust. Zero `sorry`s.
- `enable_lsp` defaults false and is **never** backfilled true.
- No custom / user-defined language-server executables in v1. No `ToolCeiling.lsp_servers`.

- Enabling the `tools` self-config category delegates authority to activate any detected built-in catalog server. `tools explain` must say so.
- Pool entries are `Starting` / `Ready` / `Retiring`. Starting counts toward caps (4 per session+behavior, 16 per host). A borrow is a lease. LRU only among zero-lease `Ready` entries. If every candidate is starting or leased, return `serviceUnavailable`. Never kill an active request to make room.
- Reuse MCP's no-lock-across-I/O discipline **plus** an explicit per-key `Starting`/singleflight. Do not claim MCP already singleflights a fresh key.
- No reconcile "slot drained" callback. `retire_slot` detaches a join; `on_slot_retired` runs before that join. Rely on digest + zero-lease LRU + 5-minute TTL.
- `session::close_session` stays persistence-only (`crates/gents/src/session/sessions.rs`). The runtime/oneshot owner that has both the session id and the pool calls `LspPool::close_session`. `run_agent` awaits `lsp_pool.shutdown()` after `shutdown_slots`.
- Omitted `network_mode` → inherit off macOS (tool available). Explicit `network_mode: disabled` under `Unrestricted` → `DisabledNetworkUnenforceable` / `policyDenied`. Never coerce explicit `disabled` to `inherit`.
- Three URI rules: inbound escape → terminal `policyDenied`; WorkspaceEdit escape → abort preflight, no writes; read-output structured location escape → omit/redact + note + complete. Hard guarantee is structured URI/location fields only.
- Format-on-write stays under the file-mutation lock. Release the lock **before** waiting for diagnostics. Render only diagnostics whose document version is at least the captured version.

- Biome / SwiftLint run only during explicit `lsp` `diagnostics`. They do not participate in writethrough.
- Action start matrix: `status` and `reload` never cold-start. Capabilities and semantic actions may. Writethrough never starts a client.
- Do **not** add `NativeTool::Lsp`. `LspTool` is assembled in `ToolSurface::build_tools` with `runtime.lsp_pool`.
- `run_managed_exec` callers are bash and the fs-runner. CLI tools are **not** callers. Rebuild `run_managed_exec` on `spawn_managed_process`.
- `ActiveExecGuard` stays. Snapshots distinguish `ForegroundCommand` vs `PersistentService` so a five-minute rust-analyzer is not a wedged tool call.

```lean
import Proofs.ToolPolicy.Types

namespace Lsp
open ToolPolicy

inductive LspAction where
  | diagnostics | definition | typeDefinition | implementation | references
  | hover | symbols | status | capabilities | reload
  | rename | renameFile | codeActionsList | codeActionsApply
  | requestRead | requestWrite
  deriving DecidableEq, Repr

def LspAction.mutates : LspAction → Bool
  | .rename | .renameFile | .codeActionsApply | .requestWrite => true
  | _ => false

inductive LspMutationSource where
  | foregroundReturnedEdit
  | serverApplyEdit
  deriving DecidableEq, Repr

def lspAdvertised (lsp : Bool) (file : FileCap) : Prop :=
  lsp = true ∧ file ≠ FileCap.off

def lspActionAuthorized (lsp : Bool) (file : FileCap) (action : LspAction) : Prop :=
  lspAdvertised lsp file ∧ (¬action.mutates ∨ file = FileCap.readWrite)

def lspApplyAuthorized (lsp : Bool) (file : FileCap) (src : LspMutationSource) : Prop :=
  lspAdvertised lsp file ∧
    file = FileCap.readWrite ∧
    src = LspMutationSource.foregroundReturnedEdit

instance (lsp : Bool) (file : FileCap) : Decidable (lspAdvertised lsp file) := by
  unfold lspAdvertised; infer_instance
instance (lsp : Bool) (file : FileCap) (action : LspAction) :
    Decidable (lspActionAuthorized lsp file action) := by
  unfold lspActionAuthorized; infer_instance
instance (lsp : Bool) (file : FileCap) (src : LspMutationSource) :
    Decidable (lspApplyAuthorized lsp file src) := by
  unfold lspApplyAuthorized; infer_instance
```

Do **not** mix `Bool` and `Prop` in the theorem statements. Cases emit JSON via `decide (lspAdvertised …)`.
