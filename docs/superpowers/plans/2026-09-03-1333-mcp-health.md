# #1333 MCP Service Health Single Owner Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** MCP tool-service health has one classification, computed in Rust from the Lean-mirrored state machine and shipped on the wire; the CLI and desktop stop re-bucketing the persisted string and the desktop stops inventing a `stuck` state from a wall clock.

**Architecture:** `gents-protocol` gains `tool_service_health::ToolServiceHealthState` (the persisted vocabulary `healthy | degraded | evicted | reconnecting`, strict parse) with `project() -> ToolServiceHealthProjection` (`healthy | stale | unreachable`). `gents::health_checker::HealthStateInternal` becomes a thin alias/`From` of it so the runtime's Lean fence keeps fencing one type. The bridge's `MCPServiceHealthView` gains `display_state: String` (the projection, like `BackendHealthView.display_state`) and the CLI's `count_health_status` buckets by the projection. `mcpHealthModel.ts` keeps labels and glyphs only; `stuck` and the elapsed-clock heuristic are deleted.

**Tech Stack:** Rust (gents-protocol, gents, gents-cli, gents-desktop-bridge), ts-rs generated TS, TypeScript (gents-desktop-operations).

**Spec:** GitHub issue #1333. Rubric: `docs/superpowers/specs/2026-08-17-mobile-session-sync-design.md` "Removed concepts" (no synthetic state from elapsed time, no UI-local interpretation of raw rows).

## Global Constraints

- `Proofs/MCPHealth/State.lean` stays the model; the runtime's `lean_vocab` fence for MCP health keeps parsing `toDefraDB` from the Lean source and must still pass against the protocol type's `as_str`.
- No `stuck` state anywhere unless it is modeled in Lean first. This plan deletes it; if the product wants it back, that is a Lean change in a later PR.
- Strict parse: an unknown persisted status is `None`/an error, never silently `unknown` in Rust. The TS keeps one `unknown` fallback only for a missing `displayState` (never for a value it does not recognize: the TS switch is exhaustive over the three projections).
- Bridge contract: adding a required field to `MCPServiceHealthView` is additive; bump MINOR (6.0 → 6.1) and regenerate the hash via the crate's own test.
- Net code deletion.
