# #1334 One Subagent Tree Builder Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The subagent tree projection (root request → descendant nodes and edges, depth-bounded, terminal subtrees pruned) has one owner in `gents`; the CLI HTTP route and the desktop bridge command both call it. The duplicated deadline-expiry comparison in the CLI has one helper.

**Architecture:** The bridge's `snapshot/subagent_tree.rs` (`build_subagent_tree`, `build_local_subagent_tree`, `SubagentTreeAccess`, `TreeQueryAccess`, `effective_subagent_tree_max_depth`, depth constants) is the better-factored of the two copies (it already abstracts the query access). Move it into `gents::subagent_tree` (new module next to `descendant_graph`), generalizing `TreeQueryAccess` over `DescendantGraphAccess` so the CLI's local node and the bridge's local/peer access both fit. The CLI's `http/subagent_tree.rs` keeps only the axum handler and the JSON DTO conversion; the bridge keeps only the Tauri command and view conversion. Terminality comes from `DescendantEdge::is_terminal()`.

**Tech Stack:** Rust (gents, gents-cli, gents-desktop-bridge).

**Spec:** GitHub issue #1334 and its correction comment (the bridge's `operations_snapshot.rs` `TERMINAL_LIFECYCLE_STATES` is tool-call vocabulary and stays; see #1339 for a tool-call-side owner).

## Global Constraints

- Same output for the same inputs: capture the CLI route's JSON and the bridge command's view for a fixed fixture tree before the move (existing tests in both files do this) and keep them green.
- Depth defaults (`DEFAULT_SUBAGENT_TREE_MAX_DEPTH = 8`, `HARD = 32`) live once, in `gents`.
