# #1340 DesktopInitSummary Single Owner Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The local-runtime init summary has one wire shape: the Rust struct serializes camelCase and generates the TypeScript type; the hand-written TS type and its invented field are deleted.

**Architecture:** `gents_desktop_core::local_runtime::DesktopInitSummary` gains `#[serde(rename_all = "camelCase")]` and a `ts_rs::TS` derive, and is exported by the bridge's `typegen` like every other view. `packages/gents-desktop-client/src/types/bootstrap.ts` re-exports the generated type instead of declaring its own.

**Tech Stack:** Rust (serde, ts-rs), TypeScript.

**Spec:** GitHub issue #1340. Bug is live on `main`: `apps/gents-desktop/src/hooks/desktopShellPeerActions.ts:55` reads `summary.agentDid` but the bridge sends `agent_did`.

## Global Constraints

- No `?:` optional TS field and no `??` fallback kept for the old snake_case shape.
- Generated TS is produced by `cargo test -p gents-desktop-bridge` (the `typegen` export test), never hand-edited.
- The bridge wire-schema hash is regenerated by the crate's own test if the exported set changes; `contracts/desktop-bridge.json` and `packages/gents-desktop-client/src/client.ts` follow.
- Net code deletion.
