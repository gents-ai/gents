# #1335 Charged-Usage Owner for Goals and /self Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `Goal.tokens_used` and the CLI `/self` context indicator are computed by the same owners every other budget consumer uses: `provider_usage` for charged tokens and `provider_input::budget` for the input budget.

**Architecture:** `goal.rs::session_token_usage` stops computing "fresh input + completion" and sums `provider_usage::sum_charged_from_persisted_parts` over the same `InferenceCall` rows the request ledger rehydrates from (no `call_state` filter; the ledger reads all rows for a request). The `/self` indicator reports utilization against `effective_input_budget(context_window, compaction_threshold)` exported from `gents`, instead of `current / context_window`.

**Tech Stack:** Rust.

**Spec:** GitHub issue #1335.

## Global Constraints

- One formula for charged tokens: `input_tokens + output_tokens` where input already includes cached input (`provider_usage.rs:20`). No second "fresh input" metric survives under the name `tokens_used`.
- Ledger alignment: `completion_factory.rs:182-210` sums every `InferenceCall` row for the request with no `call_state` filter; goals use the same row set.
- Net code deletion.
