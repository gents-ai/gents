# Formal coverage audit — defra-agent runtime

Date: 2026-05-13

Scope: every runtime subsystem under `crates/defra-agent/src/` is reviewed against the Lean modules listed in `crates/defra-agent/proofs/Proofs.lean` (the imported set, post-#181) and the TLA+ artifacts under `crates/defra-agent/proofs/tla/`. A subsystem is "modeled" only when a theorem or property closes the load-bearing transitions/invariants; "operational" Rust paths that the README or specs label as boundary work are flagged as gaps rather than passes. Coverage is the question; correctness of individual proofs is trusted. This audit is read-only and contains no code changes.

Bottom line: the per-node lifecycle core (request, process, persistence, storage observation, inference call, runtime/apply reconcile, triggers, session queue, session recovery, command/tool policy, tool-call lifecycle including the subagent bridge, client/desktop projection) is in Lean. Cross-node behavior has two TLA+ artifacts (`ReversePairing`, `SubagentCompletion`) and one matching Lean handler-idempotence file (`ReversePairingHandlers`). The largest gaps are: streaming/live-tail response lifecycle, AgentMessage/transcript persistence ordering, the compaction/context-management pipeline, MCP health/eviction lifecycle, identity (`AgentPrincipal`/`AgentBehavior`/`AgentDeployment`) split, and the one-shot tool execution path. Each of those is a runtime surface whose behavior is currently asserted only by Rust tests and prose.

## Per-entity verdict

- ✓ Request lifecycle (9 states): every legal transition, the 9×9 enumeration, and S1/S3/S4/S5/S6/L1/L2/L3 are in `Proofs/Request/*` and `Proofs/Properties/{Safety,Liveness,Decidable}.lean`. Conformance rows feed `state_machine_conformance::generated_request_transition_cases_cover_lifecycle_policy`. No coverage gap.
- ✓ Pre-claim TTL: `claim_requires_ttl_open` and `claim_with_ttl_bounds_time` (`Proofs/Request/Properties.lean:131,:160`) close the model side; Rust converts stale pendings to `dead/Stale` per the deadline audit. No coverage gap.
- ✓ Request interrupt propagation: `Proofs/Composed.lean:203,:237` proves an interrupted request cancels every live linked `InferenceCall` and every live linked tool. The live-preemption gap is a runtime/OS concern flagged by the deadline audit; the formal model is sound.
- ✓ Same-session request queue (R4a): `Proofs/Session/*` is fully imported (`Proofs.lean:11`). `active_at_most_one`, `claim_next_selects_earliest`, `transition_preserves_uniqueCoalescedQueueKeys`, and `terminal_history_monotonic` close the FIFO and coalescing invariants the R4 spec required.
- ❌ Watcher / pending pickup / cooldown: nothing in `Proofs/` covers the watcher fallback poll (30 s), processed-id cooldown, or dropped-gossip resync. The system relies on these to converge after a missed DefraDB event, and the conformance ledger has no entry. **Leverage:** modeling watcher convergence would let us prove "every persisted pending request is eventually claimed under fair gossip + fallback poll," and would surface the dropped-event resync gap in `EventSource`/`SubagentSource` simultaneously; leaving it open means missed-event behavior is asserted only by the integration tests that simulate gossip drops, which is the same shape as the bugs the formal program is meant to prevent.
- ⚠️ Trigger engine dispatch: T1–T4 are closed in `Proofs/Triggers/*` and Rust consumes generated dispatch cases. The trigger *result writeback* (advancing `next_run_at`, `fire_count`, `last_status`) is `tokio::spawn` best-effort — a failed update silently refires the same due schedule (deadline audit ⚠️ #7). **Leverage:** a Lean writeback-convergence model would let us assert "fired schedules monotonically advance `next_run_at` or stay refireable but not both"; leaving it open means schedule double-fire bugs are caught only at production-scale.
- ✓ Runtime reconcile: `Proofs/RuntimeReconcile/{State,Transition,Executable}` with monotonic generation, coherent preservation, router observed-generation readiness, and in-flight retirement safety. The control-watcher debounce timer is operational and intentionally outside the model.
- ✓ Apply reconcile: `Proofs/ApplyReconcile/*` covers ordering, reference closure, field separation, prefix safety, convergence, and re-apply idempotence. The non-atomic apply storage limitation is explicit in the README ("Apply Storage Atomicity").
- ✓ Pairing reconcile (peer collections — #107): `Proofs/PairingReconcile/*` (just landed) closes per-peer convergence with `reconcile_converges_in_finite_steps`; `disagreementCount` is the symmetric-difference progress measure. The cross-node sibling `tla/ReversePairing.tla` (#162) covers fair convergence over lossy RPCs.
- ✓ Reverse-pairing handler idempotence: `Proofs/ReversePairingHandlers.lean` proves install/teardown handlers are set insert/erase with the four idempotence laws. This discharges the receiver-side obligation surfaced by the TLA+ model.
- ⚠️ Startup recovery sweep: L3 `recovery_convergence` proves a finite set of stuck requests reach terminal, but does not enumerate the *concrete* sweeps (`RequestLifecycle::recover_all`, `ToolCallLifecycle::recover_all`, missing `InferenceCall` sweep). **Leverage:** an explicit recovery-action enumeration would catch the deadline audit's #6 gap (no startup sweep for stale `InferenceCall.call_state`) and the #4 gap (detached subagent tool rows skipped); without it, every new persistent collection needs its own ad hoc startup recovery test.
- ✓ Tool-call lifecycle: `Proofs/ToolExecution/{State,Transition,Properties}` covers T1–T5 (terminal irreversibility, deadline-implies-`timedOut`, completion-implies-committed, cancellable iff non-terminal, live calls reach terminal). Cross-layer C1/C1'/C2/C3 lift deadline/interrupt effects into the composed state. The native-tool single-poll boundary is not a Lean failure — Lean's model is sound and Rust deviates.
- ⚠️ Tool-call recovery: the live convergence is modeled (`live_call_reaches_terminal`), but the persisted-row sweep (`recover_all`) and the *skip* behavior for detached subagent rows are operational. **Leverage:** a sweep-action conformance contract would expose the deadline audit's ❌ "subagent bridge terminal lifetime" gap directly; right now Rust silently leaves detached rows unrecovered with no failing test.
- ⚠️ Native tool runtime: `timedOut_requires_deadline_exceeded` is the relevant Lean fact, but it is an implication, not a liveness property. T5 `live_call_reaches_terminal` is constructive in Lean and operational in Rust — the model assumes the runtime can advance time, which native filesystem traversal blocks (deadline audit). **Leverage:** modeling cooperative-vs-preemptive boundaries in Lean would make the gap explicit (e.g., a `preemptible` predicate) and force the runtime to pass a witness; leaving it open means "live convergence" is true in the model but false for `glob`.
- ❌ One-shot tool execution: the deadline audit flagged this as ❌ and the formal-coverage picture is identical: `oneshot.rs` builds tools without `runtime::wrap_tool`, runs with no request lifecycle, and the hook has no active request id. **Leverage:** until one-shots get a request lifecycle, the entire `Proofs/Request/*` model does not apply — a Lean-mandated boundary annotation would make this an accepted boundary instead of a silent deviation.
- ⚠️ InferenceCall admission + slot accounting: S7/S8/S9 plus `SlotAccounting.lean` are the live model; capacity invariants, slot reconstruction, and permit-drop terminalization are proved. **Leverage:** the missing startup sweep for stale `queued`/`running` rows (deadline audit #6) is the gap; closing it requires the recovery-action enumeration above. Leaving it open means crashed-call rows pollute slot accounting until a new runtime_instance_id wins out.
- ✓ Fleet slot reconstruction: `Proofs/Fleet.lean` and `Proofs/InferenceCall/SlotAccounting.lean:171` close S7/S8/S9 over the persisted row layout. No gap.
- ⚠️ MCP service connection / pool / health: `ToolRetryDisposition` and the retry-eligibility model live in `Proofs/ToolExecution/Policy.lean`, with conformance in `mcp_pool::tests::tool_retry_disposition_contract_cases_match_mcp_pool_policy`. The 30 s probe, 120 s staleness, 5 s probe timeout, and eviction state machine are operational. **Leverage:** modeling probe/eviction as a state machine would catch flapping-connection-pool bugs before they reach prod; leaving it open means health-driven pool eviction has no contract beyond Rust tests.
- ⚠️ MCP `call_tool` / preflight deadline: covered indirectly through the parent request/tool-call deadline. **Leverage:** the 30 s/120 s/300 s policy variants are not enumerated as Lean cases, so a future change to those policies has no conformance fence; this is the same shape gap as schedule writebacks.
- ✓ Stream liveness / finalize / live-tail: Proofs/StreamingResponse/* models the server-side streaming → terminal state machine. streamIdle_eventually_terminal closes the deadline-audit ⚠️ stream-liveness verdict; completed_state_has_empty_liveTail formalizes the #64 obligation; recovery_path_preserves_liveTail encodes the runtime recovery-vs-normal asymmetry as a positive theorem.
- ✓ Subagent bridge transitions: `Proofs/Subagent/Properties.lean` closes B1–B6 plus INV-DEPTH/INV-LINK/INV-UNIQUE. The bridge is the most invariant-dense subsystem in the codebase and Lean state is ahead of Rust's R4 wiring.
- ⚠️ Subagent source dispatch: the dispatch case is covered by `Proofs/Triggers/Dispatch.lean`; the missed-event resync and orphan-child materialization timing are operational. **Leverage:** modeling the event-drop resync would directly address deadline audit #5 (missing live rescan for dropped subagent events); leaving it open means R4/R5 deployments retain a "may have missed child spawns" log line as the only operational signal.
- ✓ Subagent completion projection (in-process, R4a/R4b): the composition of session-queue (`Proofs/Session/*`) and bridge transitions covers coalesced wake-up enqueue, drain, and bridge advance. The orchestrator in `subagent_completion.rs` is operational glue around already-formal pieces. The R4 ledger entries for `AwaitMode`/`CancelPolicy`/`ChildTerminal` are still follow-up coverage; vocabulary parity is closed but consumer rows are pending.
- ✓ Cross-deployment subagent completion projection (#176): `tla/SubagentCompletion.tla` has nine invariants and a liveness property closed at `Child={c1,c2}, MaxCrashes=1, MaxDrops=1` in 2 min 01 s. This is the second cross-boundary artifact (after `ReversePairing`) and closes the #175 background-mode model question.
- ❌ Replicator/gossipsub subscription persistence parity (#166): no Lean or TLA+ coverage; the reverse-pairing TLA+ README names this as a follow-up. **Leverage:** the current TLA+ assumes gossipsub state is fair; if persistence parity isn't enforced, a crash can leave a node subscribed in DefraDB metadata but not in libp2p. Closing this would tie the substrate to the formally-verified upper layer; leaving it open means the assumption that #162 relies on is asserted only by Rust integration tests.
- ❌ AgentMessage persistence + ordering: only the storage-observation layer covers it, and only at the granularity of "a mutation succeeded or failed." Tool-result dedupe (#160), hook in-flight drain, and message-append ordering have no Lean state machine. **Leverage:** ordering bugs in tool-result writeback are exactly the class of "broken retry/reissue semantics" the README lists as a target class. Modeling message-append as its own state machine (or adding it to the session model) would close the largest persistence gap in the runtime.
- ✓ AgentResponse lifecycle (streaming → terminal): closed by Proofs/StreamingResponse/*; see Stream liveness above for the cross-cutting properties.
- ❌ Compaction / context management: `Compactor` and `Truncator` are explicit traits with no Lean coverage. Compaction is currently asserted by `crates/defra-agent/src/compaction/tests.rs` only. **Leverage:** any future compaction strategy (sliding window vs. summary, token-budget-driven, structured) ships without a conformance backstop; modeling boundary preservation (no tool-call orphaning, no message reordering) would let us add new strategies without fearing transcript corruption.
- ✓ Session retry / reissue: `Proofs/SessionRecovery.lean` closes reissue deadline checks, identity preservation, and retry-budget monotonicity. Witness rows ship in `Proofs/Conformance/Contracts.lean` and Rust consumes them.
- ✓ Client turn projection: `Proofs/Client/*` plus `Proofs/ClientShell/*` close every load-bearing rule (selection preservation, transport-no-op, submit gates, stale-request cleanup). Frontend (`projectChatShell`) and desktop (Rust session-snapshot bridge) tests both consume generated witness rows.
- ✓ Command/tool execution policy: `Proofs/CommandPolicy/*` closes argv prefixes, read-only allowlists, disabled-network fail-closed, sandbox selection, and filtered env. Lean drives sandbox tests against generated cases.
- ✓ Trigger lineage / serial / latest-only: T1–T4 in `Proofs/Triggers/{Lineage,Serial,LatestOnly}`. `dispatch_materializedTriggerRequest_consistentLineage` ties dispatch output to admission execution origin. Latest-only seeded into Rust trigger-engine tests via Lean-computed `superseded_prior_ids`.
- ❌ Identity / `AgentPrincipal`/`AgentBehavior`/`AgentDeployment` split (#9): CLAUDE.md's identity-model section flags this as evolving; the runtime still uses `AgentProfile` as a single object. No Lean or TLA+ artifact models the principal/behavior/deployment separation. **Leverage:** the identity boundary is what makes least-privilege agent permissions enforceable; modeling it would settle the `amy-general`/`amy-code` vs `amy-rumination` permission boundary in proof rather than convention. Leaving it open means the security boundary that DefraDB DID-based identity is *supposed* to provide is asserted only by code review.
- ❌ P2P admin authentication (#180): the #107 design called admin auth out as a follow-up. No artifact exists. **Leverage:** the reverse-pairing RPC lane currently trusts the operator to write valid desired state. Modeling auth at the receiver gate would let us prove "an unauthorized desired write cannot install a subscription," which is the obvious next safety property after #162's convergence.
- N/A Operator liveness counters (#179): observability fields aren't a state machine. The interesting formal angle is that they consume Lean vocabularies (`ReconcilePhase`, `ProcessState`, `InferenceCallState`); if those names drift, the counter consumer test fails. Coverage is appropriate.
- N/A DefraDB document gossip: the gossip substrate is intentionally outside both Lean and TLA+. `Proofs/StorageObservation.lean` records the daemon-visible assumptions; TLA+ models lossy delivery with fairness. Engine and libp2p correctness are explicit non-goals.

## Highest-leverage gaps

Ranked by what would unlock the next product step or close the largest class of latent bugs:

1. **AgentMessage persistence + ordering (incl. tool-result dedupe #160).** Closes the largest persistence gap in the runtime, and is the lifecycle that hooks, compaction, and live-tail all depend on. Modeling this as a state machine (or extending the session model) would catch tool-result-order regressions before they manifest as transcript corruption — exactly the bug class the README names as a target. Today there is no contract for ordering between `AgentMessage` and `AgentToolCall` rows.
2. **AgentResponse / stream-liveness state machine** (closed by #190). Couples to (1), to operator visibility (#179 wants `streaming` counters), to compaction (depends on response terminal observation), and to the deadline-audit stream-liveness ⚠️. The current "L3 + S6 imply terminal commits" is true but does not pin the *streaming* path that produces those terminals.
3. **Compaction / context-management properties (`Compactor`/`Truncator`).** Compaction is the change that ships most often, has no formal backstop, and has the highest blast radius (transcript corruption). Modeling boundary preservation invariants would let new compaction strategies ship without fearing tool-call orphaning.
4. **Watcher / dropped-event resync.** A live resync model would simultaneously close `EventSource`/`SubagentSource` drop handling (deadline audit #5, #8) and the watcher fallback poll. The current "drop ⇒ warn ⇒ wait for fallback" path is a single point of formal silence.
5. **Identity (`AgentPrincipal`/`AgentBehavior`/`AgentDeployment` — #9).** The split is the precondition for least-privilege agent deployments, which is the product surface DefraDB's DID-based identity exists to enable. The security boundary lives in code-review convention today.
6. **Recovery action enumeration (startup sweeps).** Closes the deadline-audit ❌ #6 (`InferenceCall` startup sweep) and the ❌ "subagent bridge terminal lifetime" gap, and gives every future persisted collection a deterministic recovery contract.
7. **MCP health/eviction state machine.** Lowest immediate stakes but highest cumulative cost: every connection-pool bug we've shipped has been health-related. A probe/eviction state machine would let the pool's "flapping" behavior be a contract failure, not a Rust-test gotcha.
